# TSR 备课站：资料组织与扩展

## 1. 先按教学对象组织，不为每次备课另建网站

层级固定为 **课程 → 学期 → 周次 → 课堂讲稿 / 完整资料**。

- 总入口：`hub.html`。
- 唯一课程目录：`teaching-catalog.json`。首页从它读取卡片、筛选项和目标链接，不重复手写课程列表。
- 新课程路径：`courses/<course-id>/<term-id>/week-<两位数>/`。
- 每周两个稳定入口：`index.html` 为课堂讲稿，`library.html` 为完整资料。
- 原纯数学的 `index.html`、`library.html` 保持原地址；目录直接链接它们，不为统一目录而破坏已有平板收藏。
- 只列实际准备完成的周次。未知日期、未取得的材料、未发布答案不伪装成已完成。

## 2. 公私分开：原件不等于发布材料

公开仓库保存获准公开的教师备课笔记、核对后的题目与讲解、渲染资源和公开课程目录。每条独立补充解答应明确标识为教师备课推导，不能冒称老师正式答案。

**本地私有备课目录**保存原始讲义、教师邮件、来源核对记录及原件哈希；原件只读，编辑在副本上完成。学生姓名、邮箱、成绩、签到、个人日历、教室安排及认证信息不进入公开目录。新的课程若有不同的材料公开限制，须先确认边界。

此站是含答案的教师个人备课版，不是学生可见或安全投屏的课堂展示版。`noindex` 仅请求搜索引擎不收录，不是身份验证。不要把私密资料的保护寄托于“不把链接发给学生”。

## 3. 当前已经实现的目录层

- `teaching-catalog.json` 的 `version: 1` 数据模型。
- 总入口按课程筛选、按代码/标题/知识点搜索。
- 每个周次分别打开课堂流程和完整参考资料。
- 手机和平板布局、键盘焦点、读屏结果提示、加载失败直达入口。
- 目录包含 Pure Week 1 与 Linear Algebra Week 1；对应内容及发布状态由发布前核查保证。

总入口不自动同步 Blackboard、创建后续周次或核定教学分配；内容仍须按下面的来源核对与发布流程逐周准备。

## 4. 目录 schema v1

```json
{
  "version": 1,
  "updated": "YYYY-MM-DD",
  "courses": [{
    "id": "linear-algebra",
    "title": "线性代数",
    "titleEn": "Linear Algebra",
    "code": "MATH10015",
    "terms": [{
      "id": "2026-tb1",
      "title": "2026 TB1",
      "weeks": [{
        "id": "week-01",
        "number": 1,
        "title": "Week 1 · 主题",
        "topics": ["经讲义核实的知识点"],
        "status": "ready",
        "date": "YYYY-MM-DD",
        "durationMinutes": 50,
        "script": "courses/linear-algebra/2026-tb1/week-01/index.html",
        "reference": "courses/linear-algebra/2026-tb1/week-01/library.html"
      }]
    }]
  }]
}
```

路径均为站内相对路径。课程、学期、周次 ID 一经发布就保持稳定；修正文案不修改标识。目录目前仅显示 `status: ready` 的条目，`ready` 仅表示资料准备完成，不表示教学时段或分配已获确认。

## 5. 已实现的内容层与共用界面

新课程的数据放在 `content/<course>/<term>/<week>/`，构建后生成 `courses/<course>/<term>/<week>/`。每周只维护三份内容文件，不再复制整套网页逻辑：

- `lesson.json`：稳定课程标识、日期、标题、来源摘要、教学边界、时长、收尾环节下标以及 `publication` 发布状态。
- `script.json`：有序环节数组。每项包含标题、时间提示、关联参考条目 `topic`、课堂速览和详细讲稿块。英文是可说的话，中文是解释和动作提示。导航采用环节数组下标；已发布后若重排环节，应核对书签与收尾下标。
- `reference.json`：稳定的 K/A/B/C/T 条目 ID；完整题意、前提、思路、逐步解答、英文讲法、中文备注、易错点和可选替代解法、示意图。
- 本地私有 `source/`：原文件、哈希、来源与核查记录。本周为 `provenance.json`；原件和私人信息不随网站发布。

共享 `app.js` 与 `library.js` 通过页面参数选择本周数据、收尾位置、计时长度及独立的阅读设置。切到另一门课不会继承错的题号、字号或计时器。纯数学仍保留原生成来源与原网址，不强行迁移历史数据；新课程使用这一通用管线。

### 可执行的三个操作

```sh
# 只新建草稿，不覆盖已存在的周次
npm run new:lesson -- linear-algebra 2026-tb1 week-02 "Linear Algebra · Week 2"

# 填入核实内容，并明确 publication: approved 后生成页面
npm run build -- content/linear-algebra/2026-tb1/week-02

# 更新全站离线资源及内容版本
npm run cache
```

生成器会拒绝草稿、缺少双语字段、重复条目 ID、无效关联题号、未替换占位符、明显认证信息及本机路径。公式必须通过 KaTeX 渲染。输出 `coverage.json` 记录覆盖条目、讲稿环节、解答步骤及原题对应项；自动检查不能替代对原题条件和数学推导的人工核对。

课程目录单独维护：只有经过检查且准备发布的周次才加入 `teaching-catalog.json` 的 `ready` 列表。草稿不会自动出现在入口。源文件 → 校验构建 → 界面检查 → 公网发布读回，是明确分开的状态。

首次联网后，等待“离线已就绪”，再保留页面供离线使用；共享缓存含两门课程已生成的讲稿、完整参考和公式字体。浏览器若清除网站数据，需重新联网加载。离线缓存不等于云端备份。

## 6. 每增加一周的实际操作

1. **核对来源**：当前课程讲义、题单、教师说明和截止时间是否对应同一学期/周次；缺材料就标注缺口，不编造题目或答案。
2. **保存原件**：在私有目录保存原件、哈希与来源记录；与上周分开，不覆盖历史材料。
3. **准备内容**：先写完整题目与推导，再提炼一节课的主线；英文可直接说，中文解释动机；备用题必须能跳过。
4. **逐题校验**：核对条件、记号、所有子问及边界情况；构造题说清非唯一性；计算题做代回/独立算例检查。
5. **生成页面**：输出新周次路径；添加目录记录。既有链接保持不动。
6. **发布前测试**：手机/平板无横向溢出；字号与中文开关有效；公式可读；两类页面链接有效；完整性、控制台错误及公开数据隐私检查通过。
7. **发布并读回**：等待托管构建成功，检查公网版本和关键操作，再把该周标记为可用。保留差异、验证记录和可执行恢复方式。

这是可重复的工作流程，不是已经运行的自动化服务。自动抓取、排程提醒和学生分发均需另行确定范围。

## 7. 板书与学生打印材料

线性代数 Week 1 现有两个额外输出：`student-worksheet.pdf`（3 页 A4、无答案）与 `tutor-board-guide.pdf`（6 页 A4、含答案）。讲稿的 `boardGuide` 字段记录图路径与逐步双语绘制说明；课堂速览与详细模式均可展开，但默认收起答案图。

`npm run print:html` 从现有活动题目及板书说明生成两份排版 HTML。PDF 需另外打印渲染并检查，不能把 HTML 生成成功当作 PDF 已更新。学生版仅取 A1–A6 活动题意，排除 C1 待交题答案与教师备注；新增或修改题目后须重新生成 PDF、核查 A4 页数、留白和答案隔离，再运行缓存更新与发布验证。
